# Лабораторная работа. Функциональное программирование на Rust

**Цель работы:** изучить работу с итераторами, замыканиями, трейтами, макросами и модульными тестами в Rust.

За основу взяты задания [лабораторной работы №3–4 «Функциональные возможности языка Python»](https://github.com/ugapanyuk/BKIT_2022/wiki/lab_python_fp). Условия адаптированы под Rust и дополнены требованиями [лабораторной работы по Rust](https://github.com/ugapanyuk/BKIT_2022/wiki/lab_rust): разработать собственный макрос и не менее трёх модульных тестов.

## Организация проекта

Создать один Cargo-пакет с именем `lab_rust_fp`. Решение каждой задачи разместить в отдельном модуле. Для демонстрации работы модулей создать исполняемые файлы `task1.rs` — `task7.rs` в каталоге `src/bin`.

```text
lab_rust_fp/
├── Cargo.toml
├── data/
│   └── data_light.json
└── src/
    ├── lib.rs
    ├── field.rs
    ├── gen_random.rs
    ├── unique.rs
    ├── sort.rs
    ├── print_result.rs
    ├── cm_timer.rs
    ├── process_data.rs
    └── bin/
        ├── task1.rs
        ├── task2.rs
        ├── task3.rs
        ├── task4.rs
        ├── task5.rs
        ├── task6.rs
        └── task7.rs
```

Модули объявить в `src/lib.rs`. В исполняемых файлах разместить функции `main`, которые вызывают соответствующие модули и выводят примеры выполнения.

Пример запуска отдельной задачи:

```bash
cargo run --bin task1
```

Запуск обработки файла с данными:

```bash
cargo run --bin task7 -- data/data_light.json
```

Запуск тестов:

```bash
cargo test
```

## Задача 1. Выборка полей

**Файл:** `field.rs`.

Реализовать функцию `field`, которая принимает коллекцию JSON-объектов и список имён полей. Функция должна возвращать итератор по выбранным данным.

Если указано одно поле, итератор выдаёт значения этого поля. Объекты, в которых поле отсутствует или равно `null`, пропускаются.

Если указано несколько полей, итератор выдаёт объекты, содержащие только выбранные поля. Отсутствующие поля и поля со значением `null` не включаются в результат. Если ни одного подходящего поля нет, объект пропускается.

Список имён полей не должен быть пустым. При передаче пустого списка необходимо сообщить об ошибке. Исходную коллекцию изменять нельзя.

Для представления данных использовать `serde_json::Value`.

Пример исходных данных:

```json
[
  {"title": "Ковер", "price": 2000, "color": "green"},
  {"title": "Диван для отдыха", "color": "black"}
]
```

При выборе поля `title` результат должен содержать:

```text
"Ковер"
"Диван для отдыха"
```

При выборе полей `title` и `price`:

```text
{"title": "Ковер", "price": 2000}
{"title": "Диван для отдыха"}
```

## Задача 2. Генератор случайных чисел

**Файл:** `gen_random.rs`.

Реализовать функцию `gen_random(count, min, max)`, возвращающую итератор по случайным целым числам.

Итератор должен выдавать `count` чисел в диапазоне от `min` до `max` включительно. Числа должны генерироваться при обращении к итератору, без предварительного заполнения вектора.

Предусмотреть следующие случаи:

- при `count = 0` итератор не выдаёт элементов;
- при `min = max` все элементы равны указанному значению;
- при `min > max` функция сообщает об ошибке.

Например, вызов `gen_random(5, 1, 3)` может выдать:

```text
2, 2, 3, 2, 1
```

Для генерации случайных чисел допускается использовать библиотеку `rand`.

## Задача 3. Итератор без повторений

**Файл:** `unique.rs`.

Реализовать структуру `Unique` и трейт `Iterator` для неё. Итератор должен последовательно выдавать элементы исходных данных, пропуская повторения.

Требования:

1. Поддержать работу с векторами и другими итераторами, в том числе с генератором из задачи 2.
2. Сохранить порядок первого появления элементов.
3. Не изменять возвращаемые значения.
4. Использовать `HashSet` для хранения уже встреченных значений или ключей.

Предусмотреть конструктор `Unique::new` для сравнения элементов по значению и конструктор `Unique::with_key` для сравнения по ключу, вычисляемому функцией или замыканием.

Для строк предусмотреть параметр `ignore_case`. Если он равен `true`, строки сравниваются без учёта регистра. При этом в результат попадает исходное написание первой встретившейся строки. Обычный конструктор должен учитывать регистр.

Примеры:

```text
Исходные данные: [1, 1, 2, 2, 3]
Результат: [1, 2, 3]
```

```text
Исходные данные: ["a", "A", "b", "B", "a"]

С учётом регистра: ["a", "A", "b", "B"]
Без учёта регистра: ["a", "b"]
```

## Задача 4. Сортировка по абсолютной величине

**Файл:** `sort.rs`.

Дан вектор целых чисел:

```text
[4, -30, 30, 100, -100, 123, 1, 0, -1, -4]
```

Получить новый вектор, отсортированный по убыванию абсолютной величины:

```text
[123, 100, -100, -30, 30, 4, -4, 1, -1, 0]
```

Решить задачу двумя способами:

1. С использованием замыкания.
2. С использованием отдельной именованной функции вместо замыкания.

Исходный вектор не изменять. Для чисел с одинаковой абсолютной величиной сохранить исходный порядок.

При вычислении абсолютной величины учесть минимальное значение выбранного знакового целочисленного типа. Допускается использовать метод `unsigned_abs()`.

## Задача 5. Макрос вывода результатов

**Файл:** `print_result.rs`.

Разработать макрос `print_result!`, который принимает имя функции и выражение её вызова, выводит имя и результат выполнения, а затем возвращает результат.

Пример использования:

```rust
let result = print_result!("test_1", test_1());
```

Переданное выражение должно вычисляться ровно один раз.

Вывод организовать следующим образом:

- число или строка — одной строкой;
- вектор — по одному элементу на строке;
- словарь — по одной паре `ключ = значение` на строке.

Для форматирования разных типов результатов разработать трейт `PrintResult`. Реализовать его для типов, используемых в демонстрационной программе.

Написать четыре функции, возвращающие:

1. Число `1`.
2. Строку `"iu5"`.
3. Словарь с парами `"a": 1` и `"b": 2`.
4. Вектор `[1, 2]`.

Вызвать каждую функцию через разработанный макрос.

## Задача 6. Измерение времени выполнения

**Файл:** `cm_timer.rs`.

Реализовать два способа измерения времени выполнения блока кода. Для измерений использовать `std::time::Instant`.

Первый способ — структура-таймер. При создании объект сохраняет время начала. При выходе из области видимости он выводит прошедшее время с помощью реализации трейта `Drop`.

Второй способ — функция, принимающая замыкание `FnOnce`. Функция должна вызвать замыкание, после его нормального завершения вывести затраченное время и вернуть результат его выполнения.

Продемонстрировать оба способа на блоке кода с задержкой через `std::thread::sleep`.

Время выводить в секундах:

```text
time: 0.500123
```

Фактическая продолжительность выполнения может отличаться от заданной задержки.

## Задача 7. Обработка данных о вакансиях

**Файл:** `process_data.rs`.

Использовать файл [data_light.json](https://github.com/ugapanyuk/BKIT_2021/blob/main/notebooks/fp/files/data_light.json), содержащий данные о вакансиях.

Программа должна получать путь к файлу из аргументов командной строки, читать JSON и обрабатывать данные с помощью четырёх функций. Результат каждой функции передаётся следующей.

### Функция `f1`

Получить список профессий, удалить повторения и отсортировать названия. При удалении повторений и сортировке не учитывать регистр. Сохранять исходное написание первого встретившегося названия.

Использовать решения задач 1 и 3.

### Функция `f2`

Оставить только названия, начинающиеся со слова «программист», без учёта регистра.

Использовать `filter`.

### Функция `f3`

Добавить к каждому названию строку «с опытом Rust».

Использовать `map`.

Пример:

```text
Программист C# с опытом Rust
```

### Функция `f4`

Для каждой профессии сгенерировать зарплату от 100 000 до 200 000 рублей включительно и добавить её к названию.

Использовать генератор из задачи 2 и метод `zip`.

Пример:

```text
Программист C# с опытом Rust, зарплата 137287 руб.
```

Результаты каждого этапа выводить через макрос из задачи 5. Время выполнения всей цепочки измерить с помощью структуры-таймера из задачи 6.

При отсутствии пути к файлу, ошибке чтения или некорректном JSON вывести понятное сообщение об ошибке.

## Модульное тестирование

Разработать не менее трёх модульных тестов с атрибутом `#[test]`. Разместить тесты в соответствующих модулях в блоках `#[cfg(test)]`.

Рекомендуемые проверки:

- пропуск отсутствующих полей и значений `null`;
- количество случайных чисел и их принадлежность заданному диапазону;
- удаление повторений с учётом и без учёта регистра;
- порядок элементов после сортировки;
- однократное вычисление выражения в макросе;
- возврат результата из функции измерения времени;
- обработка небольшого набора вакансий.

В тестах генератора проверять свойства результата, а не конкретную случайную последовательность. Для таймера не требовать точного совпадения измеренного времени с длительностью задержки.
